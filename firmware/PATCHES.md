# Các thay đổi trên mã upstream (xiaozhi-esp32 v2.5.0)

Thư mục `firmware/` là bản xiaozhi-esp32 **v2.5.0** đưa thẳng vào repo (commit `vendor: xiaozhi-esp32 v2.5.0`).
Mọi chỉnh sửa vào **file của upstream** (ngoài thư mục board `main/boards/jarvis-helmet/`) đều được liệt kê ở đây,
để khi nâng cấp upstream có thể áp lại từng thay đổi.

Quy tắc (xem `docs/` và hợp đồng triển khai):

- Ưu tiên viết code trong thư mục board. Chỉ sửa core khi bắt buộc, sửa ít nhất có thể.
- Thay đổi hành vi của core phải được bọc bằng `#if CONFIG_BOARD_TYPE_JARVIS_HELMET` hoặc `#if CONFIG_JARVIS_...`,
  để các board khác giữ nguyên hành vi upstream.
- Code mới dùng chung (ví dụ `main/protocols/extra_headers.*`) phải trung tính: không đăng ký gì thì không đổi gì.

## Cách áp lại khi nâng cấp upstream

1. Đưa bản upstream mới vào `firmware/` (commit riêng, giống commit vendor).
2. Với từng dòng trong bảng: mở file, tìm đoạn mốc (anchor) ghi ở cột "Cách áp lại", chèn/sửa đúng như mô tả.
3. Chạy `tools/fw_build_docker.sh` với `FW_CMD="pip install -q pytest; python -m pytest scripts/tests -q"`
   (test của upstream kiểm tra thứ tự menu board, Kconfig khớp CMake, config.json hợp lệ), rồi build lại cả 4 biến thể.

Thư mục board `main/boards/jarvis-helmet/` và `firmware/tests/host/` là code mới của dự án (không phải file
upstream) nên không liệt kê ở đây. Kiểm tra bảng còn đủ: `git diff --stat <commit vendor> -- firmware
':!firmware/main/boards/jarvis-helmet' ':!firmware/tests'` và `git status` (file mới trong `firmware/main`
ngoài thư mục board) phải chỉ ra đúng các file trong bảng.
